# Didit PHP SDK (`sdk-php`)

The official Didit server-side library for PHP: `didit-protocol/sdk-php` on Packagist.
Status: in development, not released.

## Read first

- `docs/DESIGN.md` is the shared contract of all seven Didit server SDKs (`sdk-python`, `sdk-node`, `sdk-go`, `sdk-java`, `sdk-php`, `sdk-ruby`, `sdk-dotnet`). It is binding: when this code and the design disagree, the code is wrong.
- `openapi/` holds the API contract this SDK is generated from (see DESIGN.md section 3).

## Toolchain

Composer, PHPUnit, PHPStan level max, PHP-CS-Fixer, PSR-18/PSR-17 HTTP. The generator is Python 3.10+ (standard library only).

## Commands

```bash
composer install                                 # install (PHP 8.1 to 8.4)
composer generate                                # regenerate src/Resources, src/Types, src/DiditClient.php, src/Params.php, tests/Generated
composer generate:check                          # fail when the committed generated code is stale
composer test                                    # all unit tests (core, generated, contract, webhook vectors, Authentication)
composer test:live                               # live sandbox smoke tests; skipped unless DIDIT_SANDBOX_API_KEY is set
composer analyse                                 # type check: PHPStan level max over src, tests, examples
composer lint                                    # PHP-CS-Fixer check (composer lint:fix to fix)
python3 -m unittest discover -s codegen/tests    # generator tests
python3 codegen/spec_sync.py                     # fetch upstream specs, update SOURCE.json, print the change summary
composer validate --strict --no-check-lock       # package metadata
```

There is no build step: Packagist installs the tagged sources (see `.gitattributes` export-ignore).

## Layout

- Generated (never edit): `src/Resources/`, `src/Types/`, `src/DiditClient.php`, `src/Params.php`, `tests/Generated/`.
- Hand-written core: `src/Core/` (client, transport, retries, pagination, files), `src/Exception/`, `src/Webhooks/` (DESIGN 9), `src/Authentication/` (DESIGN 10), `src/File.php`, `src/RequestOptions.php`, `src/Version.php`.
- Tests: `tests/Unit`, `tests/Webhooks`, `tests/Authentication`, `tests/Generated`, `tests/Contract`, `tests/Live`.
- CI: `.github/workflows/ci.yml` (PHP 8.1-8.4, lowest deps, macOS, Windows, PHPStan, PHP-CS-Fixer, generator check, core coverage 90 %, gitleaks), `spec-sync.yml` (daily), `release-please.yml` and `publish.yml` (gated, see CONTRIBUTING.md).

## Rules

- Generated code is never edited by hand. Change the generator in `codegen/` or `openapi/overlay.json`, then regenerate; CI fails when the committed generated code is stale.
- `openapi/verification.json`, `openapi/account.json` and `openapi/webhook-vectors.json` are upstream copies; never edit them by hand. Only the spec sync workflow updates them.
- Keep the SDKs in sync (HARD RULE). Any public API change in `service-didit-verification` or `service-didit-auth` must reach the OpenAPI documents in mintlify-docs, and from there every server SDK through the spec sync pull request. A change to hand-written core behaviour that DESIGN.md describes (client options, errors, retries, pagination, webhooks, Authentication) is made in all seven SDK repositories, one pull request each, and DESIGN.md is updated in all seven in the same words.
- Feature parity across languages: a capability shipped in one server SDK ships in the other six.
- Never publish a package, push a release tag or make this repository public without Alex's explicit approval; nothing is released before the 2026-11-01 Didit release.
- Unit tests never touch the network. Live smoke tests run only when `DIDIT_SANDBOX_API_KEY` is set.
- Never commit secrets, API keys or real customer data. Fixtures are synthetic.
- `CHANGELOG.md` is generated by release-please from conventional commits; never edit it by hand.
- Public API changes need tests, README updates and a conventional commit type that matches their semver impact.
